# 描画オブジェクト：意味のレイヤーと描画部品

パスはこのパッケージのルート（`lib/topology.jl/`）基準。

## 1. 目的と範囲

あかげふの方針（2026-11-17）。描画の見た目の要求（曲線ごとの色分け、辺の強調、ラベル）を、描画関数の引数を
増やして受けない。描画関数は「意味つきの描画オブジェクト」を返し、見た目は後から変える。
点や折れ線などの描画部品は既存のライブラリ（Makie）のものを使い、自前で持つのは各部品の意味だけにする。
自前の描画エンジンは作らない。

対象は Heegaard diagram（`HeegaardCode` の描画、[heegaard-plot.md](heegaard-plot.md)）と、
virtual link・o-graph（`VirtualLink` の描画、[virtual-link-plot.md](virtual-link-plot.md)）である。
URDiagram は対象外（あかげふ、2026-11-17）。

## 2. レイヤー

| レイヤー | 持ち主 | 中身 | 変えられるか |
|---|---|---|---|
| 配置 | 各表示のモジュール | 座標と、交差構造の検査結果 | 変えない |
| 意味 | この仕様 | 要素の種類・入力上の名前・導出値、部品への参照、逆引き | 変えない |
| 見た目 | この仕様 | 選択子と属性の規則の列 | 規則を足して変える |
| 描画と出力 | Makie | 線・点・多角形・文字、テーマ、SVG・PDF・PNG、対話表示 | Makie の機能で変える |

配置は数秒かかり、検査済みという保証を持つ。見た目の変更は配置をやり直さない。

## 3. 意味の要素

### 3.1 要素が持つもの

各要素は次を持つ。

1. **種類**（§3.2 の記号）。
2. **鍵**。入力上の名前で、配列の番号ではない。曲線は成分名、交点は LC のラベル、辺は（曲線名、辺の始まりのラベル）、
   面は面の番号（`F7` など）、開口は（`ℓ_i`、`+` または `−`）。入力を変えない限り、同じ要素は同じ鍵を持つ。
3. **導出値**。入力から計算した値で、描画の座標に依らないもの（役割、符号、二角形の角かどうか）と、
   描画の結果の値（交差角）を分けて持つ。
4. **部品**。描画の座標を持つ点・折れ線・多角形の列。1 つの要素が複数の部品を持ってよい（§3.4）。

### 3.2 種類

共通の種類（Heegaard と virtual link の両方が持つ）：

| 記号 | 名前 | 部品 | 鍵 |
|---|---|---|---|
| `:curve` | 曲線の成分 | 折れ線の列 | 成分名 |
| `:edge` | 辺 | 折れ線の列 | 曲線名と始まりのラベル |
| `:crossing` | 実交点 | 点の列 | ラベル |
| `:face` | 面 | 多角形の列 | 面の番号 |

Heegaard だけの種類：

| 記号 | 名前 | 部品 | 鍵 |
|---|---|---|---|
| `:opening` | 開口の縁 | 円（折れ線） | `ℓ_i` と `±` |
| `:reference` | 基準曲線 K の一片 | 折れ線 | K の曲線名と番号。既定では見せない |
| `:port` | 開口・外枠上の端点 | 点 | 曲線名と、K との交点のラベル |
| `:frame` | 外枠 | 折れ線 | なし |
| `:point_mark` | HC の点の印 | 点 | 印の名前 |
| `:disk_mark` | HC の円板の印 | 多角形の列と外周の折れ線 | 印の名前 |
| `:region` | 領域。Σ ∖ (α ∪ β) の連結成分 | 多角形の列（その領域を作る面の多角形） | 領域の番号 |

virtual link だけの種類：

| 記号 | 名前 | 部品 | 鍵 |
|---|---|---|---|
| `:virtual_crossing` | 仮想交点 | 点 | 平面化で振られた番号 |
| `:cut_endpoint` | 切り開いた成分の端点 | 点 | 辺と側 |

向きの矢印、交差の切れ目、ラベルの文字は要素ではない。辺や交点に付く見た目として、§5 の規則で描く。

### 3.3 辺

辺は、曲線の上で、図に描かれている隣り合う 2 つの出来事にはさまれた区間である。
見た目を変える最小の単位は辺であり、辺の中で色や太さを変えない（あかげふ、2026-11-17）。
辺の鍵は、曲線名と、辺の始まりの出来事の符号付きラベル（曲線の語の文字）である。

どの出来事が図に描かれているかは、Heegaard の描画の経路で異なる（2026-11-17、第 1 段のレーンの報告で判明）。

- **基準曲線を配置する経路**（α を `ℓ_i` か `m_i` に束ねた図、点・円板の印がある図）。基準曲線 K の各片が、固定した見えない線として
  配置に入っている。出来事は、α–β の交点、K との交点、開口・外枠上の端点である。辺は LC の区間 `(曲線名, ラベル)` と一致し、
  `_hp_mark_regions` が `intervals` として計算する。
- **通常の経路**（上のどちらでもない図）。平滑化は K を持たず、`m_i`・`n_i` との交点は平滑化の後に座標を持たない。
  出来事は、α–β の交点と、開口・外枠上の端点（`ℓ_i` との交点）だけである。辺は、LC の区間を `m_i`・`n_i` との交点で
  つないだものになる。出来事を持たない閉曲線は、辺 1 本である。

開口をまたぐ辺は、ある run の終わりの部分と、同じ成分の次の run の始まりの部分の、2 本の折れ線になる。
`plot` の戻り値の `contacts` が、各 run の両端の LC ラベルを持つ（`(run 名, :start または :end) => ラベル`）。
ある run の `:end` のラベルと、同じ成分の次の run の `:start` のラベルは一致する。

### 3.3.1 面

面（`:face`）と円板の印は、基準曲線を配置する経路の図にだけ作る。面は K を含む曲線の配置の面であり、
K が座標を持たない通常の経路では多角形として定まらない。通常の経路の描画オブジェクトは `:face` を持たない。

面は役割を持たない K でも区切られるので、一つの面を塗ると、描かれていない K の線で塗りが途切れる。Heegaard diagram の領域に印を付けるときは、面ではなく領域（`:region`）を塗る（あかげふの決定、2026-11-18）。領域は Σ ∖ (α ∪ β) の連結成分である。役割を持たない K を忘れて面を貼り合わせた結果を、[Koda 変換仕様 §4.1](heegaard-koda-conversion.md#41-忘却の計算) の `forget_reference(realize_hc(hc))` から受け取る。領域の番号はその `regions` の `id`、部品はその `face_roots` の各面の多角形である。`ℓ_i` をまたぐ領域は、平面図の離れた場所に複数の部品として現れる。選択子 `face` は、その面を含む領域を選ぶ。領域は面と同じく、基準曲線を配置する経路の図にだけ作る。

### 3.4 1 つの要素と複数の部品

切り開いた曲面の図では、意味の要素と描画部品は 1 対 1 にならない。

- 1 本の曲線は、切り口で複数の run に分かれる。
- 切り口の上の交点（α が `ℓ_i` に束ねられた図、種数 1 の長方形の辺）は、2 か所に現れる。
- 切り口をまたぐ辺は、2 本の折れ線になる。
- 面は、切り口で分かれた多角形の組になる。

要素は部品の列を持ち、見た目の規則は要素の全部品に同じように効く。

### 3.5 関係

要素の間の関係を問い合わせられるようにする。見た目の選択子が使う。

- 曲線の上の辺と交点。
- 面の境界の辺（向き付きの並び）。
- 交点に接する 2 本の曲線。
- 二角形の 2 つの角（[heegaard-plot.md](heegaard-plot.md)「二角形」）。

### 3.6 逆引き

描画部品とその中の点の番号から、要素を引けること。Makie の DataInspector が返す部品と番号を要素に写し、
`inspector_label` で「V17、β2 × α1、符号 +、交差角 51°」のように表示する。

## 4. 形は変えない

描画オブジェクトの座標と検査結果は読み取り専用である。座標を変えると交差構造の保証が無効になるので、
利用者が座標を書き換える経路を持たない。形を直す入口（動かしてから再検査）は、この仕様の範囲外とする。

## 5. 見た目の規則

見た目は「選択子 → 属性」の規則の列で表す。後に足した規則が、前の規則に勝つ。既定の規則の列（テーマ）は、
<!-- XQQQ1500000 -->
既定の画風では α を `#ba433f`、β を `#255dba`、線幅を 2.5 とし、開口の縁を黒で描く。`ℓ_i` に束ねた α は正側（下段）の開口に α の色を付ける。既存の選択子 `upper_alpha` は正側の開口を指す。
<!-- XQQQ1000000 -->

選択子は種類と、鍵・導出値・関係の条件である。例：

```julia
d = drawing(hc)                                      # 配置して検査済みの描画オブジェクト
style!(d, :curve; role=:alpha, visible=false)        # β だけを見せる（現在の show=:beta）
style!(d, :curve; name="beta2", color=:red)          # 1 本だけ色を変える
style!(d, :edge; face="F7", linewidth=4)             # 面 F7 の境界の辺を太く
style!(d, :crossing; label=true)                     # 交点ラベル（現在の crossing_labels）
style!(d, :face; name=["F31","F49"], fill=(:gold,0.3))
```

属性は、`visible`、`color`、`linewidth`、`linestyle`、`fill`、`marker`、`markersize`、`label`（真偽、または要素から文字列を作る関数）、
`labelsize`、`zorder` とする。Makie の属性名に合わせ、写しを最小にする。

## 6. Makie との接続

- Makie はパッケージ拡張（`[weakdeps]` と `ext/`）で接続する。`using Topology` だけでは Makie を読み込まない。
  利用者が `using CairoMakie`（または `GLMakie`、`WGLMakie`）をしたときに拡張が有効になる。
- 拡張はレシピ `drawingplot(d)` と `drawingplot!(ax, d)` を持つ。レシピは、見えている要素の部品を、規則で決まる属性で
  Makie の `lines!`・`scatter!`・`poly!`・`text!` に渡すだけで、座標を計算しない。
<!-- XQQQ1500000 -->
  `drawingplot!` は軸の y を画面の下向きにし、SVG と同じ向きで表示する。
<!-- XQQQ1000000 -->
- 規則を足したあとの描き直しは、Makie の Observable の更新で行い、配置をやり直さない。
- 出力は Makie の `save` による。CairoMakie で SVG・PDF・PNG、GLMakie・WGLMakie で対話表示。
- TikZ のソース出力は範囲外（§10）。

## 7. 既存の描画との関係

- `plot(::HeegaardCode)` は当面そのまま残し、SVG の文字列を返し続ける。描画オブジェクトは `drawing(hc)` が返す。
  `drawing` は `plot` と同じ配置と平滑化を通り、同じ座標を持つ。
- `plot` の引数のうち座標に効かないもの（`show`、`mark_style`、`crossing_labels`）は、§5 の規則と重なる。
  Makie の出力があかげふの判定で受け入れられたら、これらの引数と自前の SVG 出力を外す。外す判断はあかげふが行う。
- 共通の種類の型は、まず `src/heegaard/` の新しいファイルに置く。最上位の描画モジュールへの移動は、
  [module-structure.md](module-structure.md) §5 の `svg_plot.jl` の移動と同じく、`Topology.jl` を編集できる段まで保留する。

## 8. 実装の段階

1. **第 1 段（Heegaard）。** 描画オブジェクトと規則、Heegaard の全種類、関係の問い合わせ、逆引き、Makie 拡張のレシピ。
2. **第 2 段（virtual link）。** `VirtualLink` の描画結果から同じ型の描画オブジェクトを作る。virtual link だけの種類を足す。

## 9. 受入

判定は、委任した側（描画の担当セッション）が自分で走らせて行う。実装者は判定の条件を変えず、変更は提案として出す。

1. **要素の数が入力と合う。** 曲線・交点・辺・面の数が、LC の語から独立に数えた値と一致する。切り口上の交点は部品を 2 つ持つ。
   - 通常の経路：Weeks（inner m）、Koda 種数 3、P28、Ozsváth–Szabó 図 2。曲線は役割を持つ成分の数、交点は α・β の語が
     共有するラベルの数。辺は、α・β の各曲線について、語の文字のうち相手の族か `ℓ_i` とラベルを共有するものの数
     （その数が 0 の閉曲線は 1）の和。面は持たない。
   - 基準曲線を配置する経路：L(2,1) の standard、Weeks の standard（`threads/PJ260922/data/261111-plot-acceptance/package-run-5/inputs/weeks-m/diagram.hc`）、
     点 z。辺は α・β の語の長さの和、面は `_lc_faces` の面の数。
2. **座標が変わらない。** 同じ入力で、`drawing(hc)` の部品の座標が `plot(hc)` の `placement` と一致する。
3. **見た目の変更で配置をやり直さない。** `style!` の前後で、配置の関数が呼ばれない。
4. **Makie で描ける。** CairoMakie で Weeks を SVG と PDF に保存できる。曲線 1 本の色の変更と、面の塗りが出力に反映される。
5. **逆引きができる。** 部品と点の番号から、交点・辺・面の要素が引ける（画面なしで、関数を直接呼んで確かめる）。
6. **Makie なしで読み込める。** Makie を入れていない環境で `using Topology` が通り、既存の描画の試験が変更なしで通る。

画像の見た目の合否はあかげふが判定する。
