# Lickorish Code（LC）: 曲面上の曲線配置の正本データ仕様

Status: 所有者指示による規範仕様（2026-11-07）。未実装。本書が正本の定義であり、既存の `docs/heegaard/input.md` の patch 文書は本書から導出される下流表現に格下げする<br>
Scope: 固定された向き付き閉曲面 Σ_g、基準曲線網 K、役割を持たない曲線の語と place。描画と保存の土台<br>
Audience: 要件定義（Astra と共同）、実装（Composer）、視覚検証（Codex astra）、レビュー<br>
Owner context: 東京科学大学 情報理工学院 数理・計算科学系 鈴木咲衣研究室

用語の正本は [Heegaard の用語と記号](heegaard-terminology.md) に置く。

## 1. 目的

o-graph の描画が real Gauss code を正本として座標を計算するのと同じ工程を
Heegaard diagramに与える。α∩β の交点語だけでは固定曲面上の同位類が決まらない
（例: 固定トーラスの基底 a, b に対し (a, b) と (a, a+b) は交点語が同じで図が
違う）ので、基準曲線網との交点を語に含めた **Lickorish Code** を正本とし、
描画座標は毎回そこから計算する。

描画器が位相的な経路を選ぶことは禁止する。三角形メッシュの最適化で配置を
決める現行方式（`layout_marked_document.py`, `marked_cut_layout.py` と、交点を
固定したスプライン `fair_marked_paths.py`）は所有者の明示的な除外であり、
これを用いた成果物は受け入れない。

### 1.1 層構造（所有者決定、2026-11-09）

土台のデータは Lickorish Code（LC）である。LC は種数 g の向き付き閉曲面、Lickorish 基準曲線網 K、曲線の語、`place` を持つ。単なるトーラス上の曲線も LC である。曲線の名前は、α・β の役割を指定しない。

HeegaardCode（HC）は LC に α・β の役割、`disk` などを加える上の層である。基点 `point` と領域係数 `weight` は、所有者の確定に従って HC に置く。支持と書式は HC 仕様 §3 に定める。語と `place` は LC、役割と `disk` は HC という区別は確定している。

曲線の実現と §6 の配置は LC が定める。数学の対象は Heegaard diagram と呼ぶ。HC の形式と追加の入力条件は [HC 仕様](heegaard-code.md) が定める。ベクトル場、twist front、framing は、これらに付随する別の構造として扱う。

### 1.2 検証の方針（所有者決定、2026-11-07）

正しさは作りで保証する。検証は後ろから補うものであり、過剰な検査は描画の
hot path を増やすので避ける。

- 既定の経路で走らせる検査は入力の検査（§4）だけとする。失敗した入力は誤りと
  して止める。
- 実装の不具合を見つける検査は、既定の経路に入れない。`DEBUG_MODE` とテストに
  置く。実装段階のテストは細かくてよく、機械的な照合を入れてよい。
- 受入段階では、既定の経路が上の条件を満たしていることを条件とする。
- 図の品質は実物の図を見て判断し、品質の代わりになる数値を作らない。
- 検証用データの大きさや検証の時間を理由に、図を返さないことはしない。
- 「同じデータなら同位」は機械検査ではなく §5 の証明で支える。

## 2. Lickorish 基準曲線網 K

種数 g ごとに固定した曲線系

    K = { l_1..l_g, m_1..m_g, n_1..n_{g-1} }

（Ahara–Sakasai 図 12.3、`src/heegaard/reference_surface.jl::lickorish_reference(g)`
の回転と貼り合わせ）。K の和集合を交点で細分した埋め込みグラフとして扱い、
K で切った各面は円板である（g = 1 で 1 枚、g ≥ 2 で g 枚。同関数が検査する）。

向きの約束:

- l_i は穴を左に見て一周する。
- m_i は l_i を 1 回横切り、l_i⁺ 側から l_i⁻ 側へ通る。
- n_i は l_i から l_{i+1} へ通り、l_i を正、l_{i+1} を負に横切る。

2×g 表示（l_i で切った 2g 穴の球面、上下の穴は (x, y) ↦ (x, −y) で対応）
では、m_i は同列の上下の穴を結ぶ縦線、n_i は隣列の穴を結ぶ上辺と下辺の
横線であり、K はそのまま「はしご」になる。

K は α, β とは独立した参照枠であり、入力の曲線ではない。表示用の切断系も
K の l であって、α ではない。

<!-- XQQQ1300000 -->
g = 0 では K も l, m, n も置かない。曲面は球面で、曲線どうしの交点と、交点を
持たない曲線の包含だけが位置を決める。

## 3. LC のデータ形式（Gauss code 形式）

Lickorish Code は、K の曲線と入力曲線を成分とする、向き付き曲面上の曲線配置の Gauss code である。入力曲線の名前は任意である。HC で α・β の役割を与える前にも、同じ語から配置を実現する。

- 成分: `l_1..l_g, m_1..m_g, n_1..n_{g-1}` をこの順で先頭に置き、続けて
  入力曲線を宣言した順に置く。各成分は交点ラベルの巡回語。例の α1、β1 も LC では成分名の文字列である。
- ラベル: 正整数。`1..3g−2` は K∩K の交点（l∩m が g 個、l∩n が 2(g−1) 個）
  で、種数ごとの定数。以降は
  K と入力曲線の交点、および入力曲線どうしの交点。
- passage sign: 語の中で各ラベルはちょうど 1 回 `+k`、1 回 `−k` として
  現れる。`−k` を持つ成分 b と `+k` を持つ成分 a について、a は b を b の
  右から左へ横切る（(b, a) が正の枠）。`lickorish_reference(g)` の符号と同じで、
  l_i∩m_i と l_i∩n_i では l_i が `−`、l_{i+1}∩n_i では l_{i+1} が `+` になる。
  上下の概念はないので、o-graph の passage sign をこの枠の向きの記録に流用する。
- crossing sign: `orientation` ベクトルは全成分の全交点で `+1` に固定する。
  `0`（virtual）は使わない。K との交点は描画の都合で入れ替えてよい記号では
  なく、曲面上の位置を決める情報である。
- 切断記号: l_i のラベルが切断記号を兼ねる。入力曲線と m, n の語を ±l ラベルで
  切ると 2×g 表示の弧になる。o-graph の `0` 切断記号と同じ役割で、位置は
  l_i の語の中に残る。

テキスト形式は 1 成分 1 行:

    l1   : -3  -1   5
    m1   :  1   7  -8
    ...

型としては既存の `VirtualLink(gauss, orientation)` が曲線の語をそのまま持てる
（`gauss::Vector{Vector{Int}}`, `orientation` は全て `+1`）。`real_only` の
planarization 経路は使わない。

### 3.1 交点を持たない曲線と place

交点を一つも持たない成分は語を空にし、`place` をちょうど一行持つ。交点のある成分の位置は語が指定する。

```text
place gamma : F2
place c1 : outer
place c2 : c1+
```

細分領域番号 `F1`、`F2`、… は、空語でない成分から作った回転系を、ラベルの昇順、各ラベルで `(−, out), (+, out), (−, in), (+, in)` の順に歩き、最初に踏んだ領域から数える。

`outer` は g=0 かつ交点が無いときの球面そのものを指す。曲線 C を領域 R に置くと、R は C の左側 `C+` と右側 `C−` に分かれる。後続の `place` はこの名前を使える。包含は木であり、輪を持たない。

`place` は LC に属する。予約済みの接頭辞 `place`、`disk`、`point`、`weight` は成分名に使わない。HC の `disk`、`point`、`weight` の書式と支持は [HC 仕様 §3](heegaard-code.md#3-hc-に置く追加情報) に置く。

## 4. LC の整合検査（描画前、すべて決定的）

1. 各ラベルがちょうど 1 回 `+`、1 回 `−` で現れる。
2. K 成分の語を K∩K ラベルに制限すると、`lickorish_reference(g)` から生成した
   種数の定数語に一致する。
3. 語から作った回転系の細分領域数からオイラー標数が 2−2g になり、K で切った各面が
   円板である。既存の `pd_code`／`regions` と同じ計算で行い、新規実装しない。
4. 円板ごとに、境界上の端点順が貼り合わせで両側一致する。

<!-- XQQQ1300000 -->
5. g = 0 なら K 成分は無く、交点があるときはオイラー標数が 2 である。
   交点が無いときは、全部の成分が空語で、`place` が `outer` を根とする木を
   作る。
6. g ≥ 1 で語が空の成分は、§3.1 の `place` を 1 行持ち、その参照先は
   実在する細分領域か、すでに置いた曲線の `+` または `−` である。`outer` は
   使わない。
7. LC の入力行は、種数、成分の語、`place` とする。HC の役割と追加行は HC の入口で読む。
8. `place` の包含に輪は無く、空語の成分はちょうど 1 回現れる。
<!-- XQQQ1000000 -->

失敗した入力は誤りとして止める。推測で埋めない。切断系と joining disk の条件は、HC を使う計算の入力条件として HC 側で検査する。

## 5. 意味

- 同じ Lickorish Code を持つ 2 つの図は、固定曲面上で ambient isotopy で
  移り合う（K を集合として保つ同位）。根拠: 各基準円板で境界を 1 本の曲線と
  して加えると連結 4 価の平面グラフになり、passage sign と語の順序で各頂点の
  回転が決まる。回転系が決まれば向き付き曲面への埋め込みは一意。円板ごとの
  同相を境界固定で恒等へ同位変形し貼り合わせる。状態: `proved/agent`。
- 逆は成り立たない。Lickorish Code は同位類の代表元（結び目図式に相当）で
  あり、同位類（結び目に相当）より細かい。データを変える同位変形は K に
  関する次の手だけ: 曲線と K の辺の二角形の生成・消去、曲線が K の頂点を
  越える、入力曲線どうしの交点が K の辺を越える。入力曲線どうしの交点構造は配置の定義の一部で
  動かない。
- 描画器は Lickorish Code を簡約しない。二角形の消去などは所有者が明示的に
  行う別操作であり、描画器に勝手な twist や経路を選ばせない。
- Dehn twist は語に直接現れる。l_i に沿う twist 1 回は、β の語に l_i に付く
  K の辺（m_i と隣接する n）との交点を 1 回ずつ加える。

### 5.1 操作は前後の語

操作は Lickorish Code の更新である。操作固有の図は要らない。記録は `before` と
`after` の 2 つの語で、両方とも §4 を通る。描画は、その 2 つがそれぞれ描ければ足りる。

この改訂で語の書き換えとして定めるのは、l_i に沿う twist の 1 回だけである。
正本は §8.1 である。交点 8 と 13 を m1、n1、β1 から除いただけの語は
オイラー標数 −6 になり、§4 を通らない。通る `before` は、それに加えて α1 を
`-7 17 -12` とした語である。`after` は §8.1 の語そのもので、α1 は
`17 -7 -12` に戻る。符号、順序、ラベル番号はこの 2 語に一致しなければならない。
逆 twist は `after` から `before` に戻す。スライド、安定化、その他の操作は、
同じ before/after 形式で保存できるが、この例から書き換え規則を推測して埋めない。

## 6. 描画アルゴリズム（規範）

### 6.1 原則

- 配置は面ごとに決定的に計算する。最適化、メッシュ、反復的な修正は使わない。
- 表示の幾何は、K で切った各面が凸になるように選ぶ。これにより面内の弧は
  直線の弦で置け、面を貼る写像は明示的な式だけになる。
- 失敗は入力または仕様の誤りとして止める。推測や緩和で埋めない。

### 6.2 表示の幾何（種数 g ≥ 2）

本体は長方形、穴は 2g 個の三角形、K の辺は直線。

- 列 i（i = 1..g）に l_i⁺（上辺側）と l_i⁻（下辺側）を置く。上下は
  (x, y) ↦ (x, −y) で対応する。
- 端の列（i = 1, g）の穴は長方形の角の直角三角形。頂点は、角、m_i との
  K 頂点（左辺または右辺上）、n との K 頂点（上辺または下辺上）。
- 中間の列の穴は上辺（下辺）から吊るした三角形。頂点は、n_{i−1} との
  K 頂点と n_i との K 頂点（上辺上）、m_i との K 頂点（内側）。
- m_1 は左辺、m_g は右辺の一部。中間の m_i は列 i の上下の穴の内側頂点を
  結ぶ縦線。n_i は上辺と下辺のうち、隣り合う穴の K 頂点の間の部分。
- 穴の三角形の各辺は 1 つの面に属する。内側の面（g−1 個）は凸八角形、
  外側の面（∞ を含む）は長方形の外部である。両者とも凸性は確定している。
- 穴の三角形の辺長は、その l の語に現れる交点数に比例させ、辺上の点の
  間隔を列や穴によらず一定に保つ。下限は列間隔の 1/4 とし、穴は大きめに
  描く。面の凸性は三角形の大きさに依らない。これは幾何の選択であり、
  最適化ではない。
- 配置はこの段階で最終であり、後から反復で整える段階は置かない。見た目の
  後処理を加える場合も、同位を保つ任意の処理として受入とは切り離す。
- 最終表示では各三角形に内接円を描き、三角形の辺上の点を内心からの放射で
  円周に移し、弧をその線分で延長する。放射写像は三角形の境界と円周の
  同相なので交点構造は変わらない。K の線は任意で表示する。
- 種数 1 は K で切ると 1 枚の面であり、通常の正方形（上下の辺 = l_1、
  左右の辺 = m_1）に描く。穴の表示はしない。

### 6.3 工程

1. **検査**: §4。
2. **K の辺上の点**: 各 K 辺について、その K 成分の語から辺上の交点の順序を
   読み、辺の内部に等間隔に置く。l の点は三角形の辺上に置き、l⁺ と l⁻ で
   同じパラメータを使う。隣り合う面は同じ点を共有する。
3. **面内の配置**: 各面について、語から弧（面の境界 2 点を結ぶ曲線の断片）
   とその上の交点列を得る。
   - 内側の面: 面そのものが凸なので、各弧を境界 2 点を結ぶ直線の弦として
     置く。弦の交点を計算し、各弧の交点列が語と一致すれば採用。
   - 外側の面（∞ を含む）: 単位円板 D をモデルとし、境界点を長方形の外周の
     弧長比の角度 ψ に置いて同じ弦の計算を行う。弦を引いた後、D の中で
     どの弦からも最も遠い点 c（弦の配置が作る領域の最大空円の中心、同率は
     辞書順）を選び、c からの距離の比 s ∈ [δ, 1]（δ は c と弦の最小距離）と
     c から見た円周上の角度 ψ で面へ写す:

         Φ(c + s(q − c)) = O + d(ψ) f(s) u(ψ),   f(s) = 1 + (κ − 1)(1 − s)/(1 − δ)

     ここで q は c からの半直線が円周を切る点、O は長方形の中心、u(ψ) は
     弧長比 ψ の外周点の方向、d(ψ) はその距離（長方形は凸なので一意）、
     κ は外枠の倍率（表示パラメータ、既定 1.5）。c は省略可能な引数とし、指定が
     なければ上の規則で自動選択する（連続した図の列で見た目を揃えたいとき
     に固定する）。s = 1 が外周、s = δ が
     外枠で、すべての弧は外周と外枠の間のアニュラスに収まる。∞ は面の
     一点にすぎず弧の同位類は ∞ を見ないので、c の選択は描画器の自由で
     あり、Lickorish Code と矛盾しない。
   - 弦の交点列が語と一致しない面（同族の弧が面内で交わる、2 本の弧が
     面内で 2 回以上交わる、など）は Tutte 埋め込みに切り替える: 境界点を
     固定し、弧を交点で細分したグラフの内部頂点を近傍の重心に置く
     （均一重み、疎な線形方程式 1 回）。面の向きがすべて正で交点列が語と
     一致すれば採用、さもなければその面を名指しして失敗。
4. **貼り合わせ**: 共有する境界点で弧をつなぐ。l の点では l⁺ と l⁻ を対応で
   つなぐ。
5. **仕上げ**（配置は 3〜4 で正本。仕上げは見た目のためで、失敗しても
   配置の出力を返す）:
   - 角の丸め: K 辺上の点と交点の折れを、隣接する事象までの距離の半分未満の
     半径の円弧で丸める。半径の条件により新しい交点は生じない。
   - 穴の円化: 三角形の内心からの放射で辺上の点を内接円へ移し、弧をその
     線分で延長する。
   - 力学的平滑化（既定で有効）: 既存の `mechanical_relaxation.jl` の
     張力・弱い曲げ・曲線間と自己と穴との反発による過減衰ダイナミクスを、
     次の不変量をハードゲートとして流用する。各曲線上の入力曲線どうしの交点列、交点の
     共有（1 頂点を両曲線が共有）、穴への不侵入、l 通過点の上下対応。各
     ステップは最小クリアランスの半分未満に制限し、不変量が破れたら差し
     戻す。K の辺は平滑化中は無視してよい（K を横切っても同位類は変わら
     ない）。点は弦の端点と交点から軽く細分するだけで、旧方式のような
     大量の点には戻さない。停止は反復上限かエネルギーの停滞で、到達しない
     ことは失敗ではない。
     所有者が 2026-11-07 に確定した既定値: 点は基本間隔 40・最小 8 で、交点と穴の
     入口の周り（弧長で最小間隔の 3 倍以内）は最小間隔、節の間は最低 3 線分、
     曲率と近接で詰める。張力 0.4（隣接点のラプラシアン）、曲げ 0.1、反発 3 で
     クーロン型 (c/d)^2/d（c=14、到達 220、線分長で重み付け）、穴の壁は同法則で
     重み 2、交点同士の反発は保険（重み 0.5、目標距離 40 まで線形）、異なる入力曲線どうしも共有
     交点の近傍を除いて反発。運動量 0.8、ステップ上限 0.5 かつ最小クリアランスの
     0.4 倍以下。違反時はその頂点の速度だけ 0 にして再試行。試行中の描画は折れ線。
6. **受入**: 画像を目視する。配置の出力（仕上げ前）の交点列と Lickorish Code
   の照合、仕上げ後の出力の不変量の再検査は、`DEBUG_MODE` とテストで行い、
   既定の経路では走らせない（§1.2）。所有者への説明に数値の指標を使わない。

### 6.4 実装への制約

- 配置段階（§6.3 の 2〜4）で使ってよい計算: 線分の交点、疎な線形方程式
  （Tutte）、放射写像、円弧による角の丸め。配置段階では三角形メッシュ、
  エネルギー最小化、スプラインの最適化、経路探索を使わない。エネルギーに
  よる変形は仕上げ段階に限り、§6.3 の 5 の不変量をゲートとして許す。
- 既存コードの流用: 語の型と面の計算は `VirtualLink`（`set_data!`,
  `pd_code`, `regions`）、K の定数は `lickorish_reference(g)`、仕上げの
  力学は `mechanical_relaxation.jl`、SVG の出力は既存の描画器の最小限の
  部分。`layout_marked_document.py`,
  `marked_cut_layout.py`, `fair_marked_paths.py` とその検証連鎖は呼ばない。
- passage sign と `pd_code` の slot 約束の対応は実装側の変換として固定し、
  §8.1 の例で χ = −2、§8.2 の例で χ = −4 が面数から出ることをテストで示す。本仕様の
  符号の意味（§3）は変えない。

### 6.5 平滑化の差し戻しと性能の目標

本節は所有者が指定した未実装の目標である。既存実装の達成値は、対象・環境・計測結果を別に示して確認する。配置を正本とし、仕上げの途中と最終出力は折れ線で表す。

平滑化のゲートは、曲線対ごとの交差集合、穴への不侵入、入口の対応を保つために使う。差し戻しは次の二種類に分ける。これはゲートの対応を選ぶ分類であり、用語正本で定めた数学的な「破綻」の種類には数えない。

| 差し戻しの種類 | 判定と処理の目標 |
|---|---|
| 解像度不足 | 長い線分が角を切る場合や交点の周りの自由点が足りない場合は、該当線分だけ局所細分し、その頂点の速度を 0 にして再試行する |
| 制約に接触した平衡 | 細分して再試行しても同じ箇所で差し戻される場合は、この分類とする。穴の壁と同様に実行可能集合への投影で扱い、現在の受理済み配置を保つ |

判定は細分前後の同じ箇所の差し戻しで行う。移動量は §6.3 のクリアランスの制限に従う。ゲートは動いた線分とその近傍に局所化し、全線分対の探索から近傍数 k に比例する探索へ移す。これらは実装方針であり、同位の保存の確認は DEBUG_MODE とテストに置く。既定のゲートは仕上げの適用可能性の判定として使う。

種数 ≤ 3、交点 ≤ 20、点 ≤ 500 の入力から折れ線 SVG までを 1 秒以内とする。内訳の目標は配置 ≤ 50 ms、平滑化 ≤ 300 ステップとし、最大力の閾値で早期停止する。閾値の既定値は 1e-6 とする。Koda 種数 3 を計測例に含める。JavaScript の試作の約 40 ステップ/秒は、目標の達成値には用いない。

途中経過を表示する対話モードは別に設ける。規模が大きい場合はステップ上限を規模に比例させ、1 秒を超える場合は配置の図を先に返し、平滑化の終了後に差し替える。時間は環境と入出力の範囲を添えて計測する。

出典は研究リポジトリの `.research-scratch/PJ260922/261109-lickorish-drawing-mock/README.md` の「破綻時の対応方針」と「性能目標」（2026-11-09 の所有者合意）である。

## 7. 既存データの扱い

o-graph と同じ線にする。旧配置（abalone, Poincaré など）の自動変換器は作らない。
原図から Lickorish Code を書き起こして新しい正本を作る（Koda 種数 3 の転写と
同じ）。旧 SVG は o-graph の replay branch と同様、供給された参照画像として
残すだけで、受入にはならない。「復元した」とは呼ばない。

## 9. 作業分担と自走の条件

- 要件定義: 本仕様。変更は実装を止めない。所有者は事後に追認する。
- 実装（Composer）: §3 の読み込みと §4 の検査、§6.3 の 2〜5、SVG 出力。
  §8.1 の例と、twist のない β（`-5 -17`）の例の両方で、テストの §6.3 の 6 の

  数値ではなく画像で比較する。

  語を報告して止まり、緩和や推測で進めない。
